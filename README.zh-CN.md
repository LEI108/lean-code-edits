# lean-code-edits

[English](README.md) | 简体中文

`lean-code-edits` 是一个轻量级的 Codex 技能，用于减少日常开发中常见的 LLM 编码失误。

它基于一个简单判断：大多数编码代理的失败，不是因为能力不够，而是因为行为跑偏。常见表现通常是过度复杂化、引入不必要的灵活性、大范围重构，或者使用远超任务需要的验证方式。

这个技能参考了 [andrej-karpathy-skills](https://github.com/forrestchang/andrej-karpathy-skills)，并结合当前工作区做了轻量个性化调整。

这个技能让代理始终聚焦四件事：

1. 只暴露有实质影响的不确定性。
2. 用最少的代码完成请求。
3. 做精准、可追溯到需求的修改。
4. 使用与任务匹配的最小验证。

## 包含内容

- `AGENTS.md`：正式的行为准则。
- `SKILL.md`：供 Codex 使用的触发与执行说明。
- `README.md`：面向人类的概览文档。

## 解决的问题

- 代理添加用户没有要求的功能。
- 代理为一次性代码引入抽象。
- 代理“顺手清理”了不该动的周边代码。
- 代理把简单修改升级成沉重的测试或验证流程。
- 代理在安全、合理的假设已经足够时仍然提出不必要的澄清问题。

## 适用场景

`lean-code-edits` 最适合中小型编码任务，尤其是需要控制手感、边界和改动范围的时候：

- 修复 bug
- 聚焦的功能修改
- 小范围重构
- 代码评审后的跟进修改
- 常规仓库维护

当你希望 diff 更小、代码更克制、流程更少时，这个技能特别合适。

## 设计理念

这个技能带有明确倾向：

- 它偏向谨慎，但不鼓励过度思考压倒推进。
- 它把简单性和范围控制视为首要质量指标。
- 它保持验证力度与任务风险成比例。
- 如果与项目级指令冲突，它默认服从项目级指令。

## 使用方式

你可以直接把这个目录当作 Codex skill 使用，也可以把 `AGENTS.md` 的内容合并进仓库自己的 agent 指令文件中。

如果作为 skill 使用，建议流程是：

1. 遇到编码、审查、重构或维护类任务时触发该 skill。
2. 以 `AGENTS.md` 作为唯一的行为准则来源。
3. 在不需要额外流程的情况下，直接套用四项原则。

## 非目标

这个技能不适合：

- 需要更广泛架构探索的新项目设计
- 需要大量横向比较的研究型任务
- 需要比默认配置更强验证的高风险改动

在这些场景下，把 `lean-code-edits` 当作基础护栏，而不是完整操作模型。
